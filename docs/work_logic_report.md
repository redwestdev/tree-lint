# Отчет по логике идентификации

## 1. Механизм приоритетов

**Кейс**: Наличие в одном слое двух сущностей, паттерны которых перекрываются.

**Вывод**: **Порядок имеет значение**. Движок присваивает узлу ту сущность, которая первой указана в списке в конфигурации слоя.

```
entities: {
    component: {
        matches: {
            type: "directory",
            name: "[A-Z]*",
        },
    },
    special: {
        matches: {
            type: "directory",
            name: "Special*",
        },
    },
},
layers: {
    components: {
        entities: ["special", "component"], // Сначала специальный, потом общий
    },
},
 ```


## 2. Идентификация сущностей

**Кейс**: Частичное совпадение (имя совпало, но файлы внутри - нет).

**Вывод**: Сущность считается сущностью только при **полном** соответствии всем критериям совпадения. 
- Если файлы не совпадают, узел остается обычной директорией.
- Линтер генерирует предупреждение, которое помогает пользователю исправить структуру.

## 3. Логика групп

**Кейс**: Папка без внутренних сущностей, подходящая под имя группы.

**Вывод**: Группой считается только папка, содержащая внутри **другие группы или сущности**.
- Обычные папки с простыми файлами (не-сущностями) не получают статус группы.

## 4. Регистрозависимость

**Кейс**: Различие в регистре между конфигурацией и файловой системой (в среде Linux).

**Результат**: 
- **Слои и корни**: Полное игнорирование при несовпадении регистра.
- **Файлы**: Файл `Index.ts` не распознается как обязательный `index.ts`.

## 5. Патологические сценарии

- **Нахлёст корней**: Если один корень вложен в другой (например, `src` и `src/components`), дерево дублирует ветки в отчете.
- **Скрытые файлы**: Файлы с точки (например, `.useHook.ts`) полностью игнорируются сканером.
- **Дублирование требований**: Механизм проверки дочерних элементов корректно обрабатывает повторяющиеся правила (например, требование наличия ровно двух файлов типа `*.tsx`).
